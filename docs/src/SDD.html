1系統概觀與架構

系統為純前端單頁應用（SPA），靜態檔案部署於 GitHub Pages；資料與登入由 Firebase 提供。因為使用免費 Spark 方案、沒有自有後端，所有權限與資料完整性檢查都由 Firestore Security Rules 在資料庫端強制執行，前端檢查只負責使用者體驗。

圖 1-1　系統架構

1.1 設計原則

  • 資料庫即防線：前端程式可被竄改，因此每一條權限規則都寫在 Security Rules 並有自動化測試。
  • 帳本為唯一真相：transactions 只增不刪；users.balance 是帳本加總的快取，由原子交易維護，並提供對帳檢查。
  • 學生只能「申請」：學生唯一能建立的交易是「審核中的轉帳」；所有餘額變動都由教師端的原子交易完成。
  • 即時同步：以 Firestore onSnapshot 監聽，餘額與審核狀態自動更新。
  • 全有全無：每一次點數異動都在單一 writeBatch 或 runTransaction 內完成，不存在部分成功（詳見 6.0）。
  • 最小揭露：學生只看得到自己的餘額；交易文件不含任何餘額資訊。

1.2 實作現況（v1.4）

系統有兩種資料後端，實作同一個 BankApi 介面、共用同一套業務規則（src/api/shared.ts）：

後端用途切換
FirebaseApi正式版：Firebase Auth + Cloud Firestore，權限由 firestore.rules 在伺服器端強制VITE_BACKEND=firebase（.env.production）
MockApi開發、示範與自動化測試：瀏覽器內模擬資料庫預設（npm run dev）

項目決策

登入狀態瀏覽器保存登入（一人一台 iPad）；同一個瀏覽器的所有分頁共用同一個登入身分。

1.4 模擬資料庫（開發與試用）

第一版先以瀏覽器內的模擬資料庫完成全部功能，之後再移植到 Firebase（步驟見 docs/MIGRATION.md）。

元件說明
BankApi 介面前端所有畫面只依賴 src/api/types.ts 的介面；移植時新增 FirebaseApi 實作同一介面，畫面不需修改。
MockStore整份資料以單一 JSON 存在 localStorage。transact() 在記憶體副本上完成所有修改，全部成功才一次寫回，並比對版本號處理多分頁並行（對應 Firestore runTransaction）。
MockApi每個方法先依資料庫中的角色與狀態檢查權限（對應 Security Rules），業務規則與第 6 章相同。
登入密碼以 PBKDF2-SHA256（10 萬次、隨機 salt）雜湊保存；登入狀態存在分頁的 sessionStorage，可在同一台電腦以不同分頁同時登入老師與學生。
即時同步BroadcastChannel 與 storage 事件通知其他分頁重新讀取（對應 onSnapshot）。
限制資料不跨裝置同步；能操作該電腦主控台的人可直接修改 localStorage。模擬版僅供試用與驗收，正式上線需移植 Firebase。

名冊匯入相容老師現有的 account.xlsx（no / account / passwd / name）；檔案只在瀏覽器內解析，不會上傳，也不會進入程式包或 git。

2.1 為什麼選 Vue 而不是 React

  • 單檔元件（.vue）直觀：HTML、邏輯、樣式在同一檔，日後老師或其他人接手維護門檻較低。
  • 樣板程式少：表單雙向綁定（v-model）適合本系統大量的表單與勾選清單。
  • 中文文件完整：Vue 官方提供繁體中文文件。
  • 規模相符：本系統為中小型後台加行動頁面，兩者都能勝任；React 生態較大，但本案用不到。

所有金額為整數。時間欄位使用 Firestore Timestamp，由 serverTimestamp() 或 request.time 產生；顯示時轉為 Asia/Taipei。

文件 ID = Firebase Auth uid。一位教師 + 31 位學生。

5身分驗證與授權

5.1 帳號格式

  • 使用 Firebase Auth「電子郵件 / 密碼」登入。學生不需要真實 email，登入畫面輸入名冊帳號，程式轉為 {帳號}@student.hspsbank.local。
    • 此網域不收信，僅作為識別；實作時先於 Emulator 驗證格式可被接受。
  • 教師使用自己的真實 email，可使用 Firebase 內建的「忘記密碼」信件。
  • 登入狀態使用 browserLocalPersistence（一人一台 iPad，保持登入）。

5.2 角色判斷

  • 角色存於 users/{uid}.role，Security Rules 以 get() 讀取判斷；前端路由守衛只作為體驗輔助。
  • 名冊制：Auth 帳號必須在 users 有對應文件且 active == true，才有任何讀寫權限。因此即使有人用公開的 API 金鑰自行註冊 Auth 帳號，也無法存取任何資料。

5.3 帳號生命週期

動作做法
初始化教師於 Firebase Console 建立教師 Auth 帳號，再執行 node scripts/admin.mjs init-teacher <email> 寫入 users/{uid}（role = teacher）。只做一次。
建立學生後台 Excel / CSV 名冊匯入：以第二個 Firebase App 實例呼叫 createUserWithEmailAndPassword，教師本身的登入不受影響；成功後由教師身分寫入 users/{newUid}。
學生改密碼學生於個人頁輸入舊密碼重新驗證後，呼叫 updatePassword。
重設學生密碼免費方案下瀏覽器無法修改他人密碼，因此由教師在電腦執行 node scripts/admin.mjs reset-password <學號> <新密碼>（Admin SDK）。
停用後台將 active 設為 false（可批次）；Rules 立即拒絕其所有存取。
刪除後台批次刪除 users/{uid}，同一個交易內駁回相關審核中轉帳、刪除其收款碼；transactions 保留（含雙方姓名座號快照）。Firebase Auth 登入帳號需以 Admin SDK 腳本刪除（admin.mjs delete-users）。

6核心流程設計

所有會改變餘額的操作都使用 Firestore runTransaction（讀取後寫入，衝突時自動重試），確保多人同時操作仍正確。

6.0 原子性（全有全無）保證

對應 PRD BR-17。每個操作涉及的所有文件都在同一個 Firestore 原子單位內寫入：伺服器要嘛全部套用，要嘛全部不套用；中途斷線也不會留下部分結果。

操作機制同時寫入的文件
送出轉帳申請writeBatch + Rules getAfter()新交易（pending）＋ 收款碼標記已使用。Rules 要求兩者同時出現，缺一即整批拒絕。
核准轉帳runTransaction付款人餘額 − ＋ 收款人餘額 ＋ ＋ 交易狀態 approved
駁回轉帳runTransaction交易狀態 rejected（先確認仍為 pending）
個別 / 批次加扣點runTransactionN 位學生餘額 ＋ N 筆交易
小組獎勵runTransactionN 位學生餘額 ＋ N 筆交易 ＋ 1 筆 groupAwards
沖正 / 整批沖正runTransaction相關學生餘額 ＋ 沖正交易 ＋ 原交易 reversedBy
  • 並行衝突：runTransaction 讀取的文件若在提交前被他人修改，SDK 會自動重試（最多 5 次），並以最新資料重新檢查餘額與狀態。
  • 防重複送出：按鈕送出後立即停用，直到收到結果；轉帳申請綁定一次性收款碼，就算重送也會被 Rules 拒絕。
  • 結果不明時（例如送出後斷線）：畫面顯示「確認中」，重新連線後讀取最新狀態，確認後才顯示成功或失敗，不自動重送。
  • 離線：停用 Firestore 離線寫入佇列，避免之後連線時「延遲生效」。

6.1 學生送出轉帳申請

以 writeBatch 同時寫入兩份文件，Rules 用 getAfter() 確認兩者一致，收款碼因此只能被使用一次。

const txRef = doc(collection(db, 'transactions'));      // 預先取得 ID
const batch = writeBatch(db);
batch.set(txRef, {
  type: 'transfer', status: 'pending', amount,
  fromUid: me.uid, fromName: me.name, fromSeatNo: me.seatNo,
  toUid: code.toUid, toName: code.toName, toSeatNo: code.toSeatNo,
  participants: [me.uid, code.toUid],
  title: `轉帳給 ${code.toName}`, note, category, codeId,
  createdBy: me.uid, createdAt: serverTimestamp(), ...nullFields,
});
batch.update(doc(db, 'paymentCodes', codeId), { used: true, usedBy: me.uid, txId: txRef.id });
await batch.commit();   // 任一條件不符 → 整批失敗

6.2 教師核准轉帳

await runTransaction(db, async (t) => {
  const tx = await t.get(txRef);
  if (tx.data().status !== 'pending') throw new BankError('ALREADY_DECIDED');
  const from = await t.get(userRef(tx.data().fromUid));
  const to   = await t.get(userRef(tx.data().toUid));
  const amt  = tx.data().amount;
  if (from.data().balance < amt) throw new BankError('INSUFFICIENT_BALANCE');
  const fb = from.data().balance - amt, tb = to.data().balance + amt;
  t.update(from.ref, { balance: fb, updatedAt: serverTimestamp() });
  t.update(to.ref,   { balance: tb, updatedAt: serverTimestamp() });
  t.update(txRef, { status: 'approved', decidedBy: teacherUid, decidedAt: serverTimestamp() });
});
  • 駁回：同樣以 runTransaction 先確認仍為 pending，再更新 status = 'rejected'、rejectReason、decidedBy / decidedAt，不動餘額。
  • 核准所選：依送出時間先後逐筆執行上述交易，逐筆回報結果（成功或餘額不足），不會因一筆失敗而中斷。

6.3 個別 / 批次加扣點、小組獎勵

三者共用同一個函式 applyAdjustments(items, meta)，在單一 runTransaction 內完成：

  1. 讀取所有目標學生的 users 文件（全班最多 31 筆）。
  2. 扣點時檢查每位學生餘額，不足者列入錯誤清單並中止（批次扣點畫面會先讓老師排除不足者）。
  3. 為每位學生寫入 users.balance 與一筆 transactions（status = 'approved'，共用 batchId）。
  4. 小組獎勵另寫一筆 groupAwards/{batchId}。

單次交易最多 500 個寫入；全班 31 人 × 2 + 1 = 63 個寫入，遠低於上限。

小組獎勵：並列名次
champions 與 runnersUp 皆為陣列，UI 以複選實作。當某名次選了 2 組以上時，交易的 group.tied = true，學生明細顯示「並列冠軍」。送出前查詢 groupAwards 中 awardDate == 當日 且 reversed == false，若已有紀錄則跳出確認對話框。

7Firestore Security Rules

以下為設計階段的規則草案；正式版規則以專案中的 firestore.rules 為準（時間欄位改為毫秒數、教師可管理收款碼與刪除學生帳號），並已由 30 項規則測試於 Firebase 模擬器驗證（見測試紀錄）。

rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {

    function signedIn()  { return request.auth != null; }
    function userDoc(uid) { return get(/databases/$(db)/documents/users/$(uid)).data; }
    function me()        { return userDoc(request.auth.uid); }
    function isActive()  { return signedIn()
                             && exists(/databases/$(db)/documents/users/$(request.auth.uid))
                             && me().active == true; }
    function isTeacher() { return isActive() && me().role == 'teacher'; }
    function isStudent() { return isActive() && me().role == 'student'; }

    // ---------- 帳戶 ----------
    match /users/{uid} {
      allow read:           if isTeacher() || (isStudent() && request.auth.uid == uid);
      allow create, update: if isTeacher();
      allow delete:         if isTeacher() && resource.data.role == 'student';  // 交易紀錄保留
    }

    // ---------- 設定類：學生唯讀 ----------
    match /groups/{id}      { allow read: if isActive();  allow write: if isTeacher(); }
    match /presets/{id}     { allow read:  if isTeacher()
                                    || (isActive() && resource.data.showToStudents == true
                                                   && resource.data.active == true);
                              allow write: if isTeacher(); }
    match /settings/{id}    { allow read: if isActive();  allow write: if isTeacher(); }
    match /groupAwards/{id} { allow read, write: if isTeacher(); }

    // ---------- 一次性收款碼 ----------
    match /paymentCodes/{codeId} {
      allow get:  if isStudent();
      allow list: if false;                          // 禁止列舉
      allow create: if isStudent()
        && codeId.matches('^[A-HJ-NP-Z2-9]{8}$')
        && request.resource.data.keys().hasOnly(['toUid','toName','toSeatNo','createdAt','expiresAt','used'])
        && request.resource.data.toUid    == request.auth.uid
        && request.resource.data.toName   == me().name
        && request.resource.data.toSeatNo == me().seatNo
        && request.resource.data.createdAt == request.time
        && request.resource.data.expiresAt <= request.time + duration.value(10, 'm')
        && request.resource.data.used == false;
      allow update: if isStudent()
        && resource.data.used == false
        && request.time < resource.data.expiresAt
        && resource.data.toUid != request.auth.uid
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['used','usedBy','txId'])
        && request.resource.data.used == true
        && request.resource.data.usedBy == request.auth.uid
        && getAfter(/databases/$(db)/documents/transactions/$(request.resource.data.txId))
             .data.codeId == codeId;
      allow delete: if isStudent() && resource.data.toUid == request.auth.uid
                      && resource.data.used == false;
    }

    // ---------- 帳本 ----------
    match /transactions/{txId} {
      allow read:   if isTeacher() || (isStudent() && request.auth.uid in resource.data.participants);
      allow create: if isTeacher() || validTransferRequest(txId);
      allow update: if isTeacher() && validTeacherUpdate();
      allow delete: if false;                         // 帳本只增不刪
    }

    function validTransferRequest(txId) {
      let d      = request.resource.data;
      let before = get(/databases/$(db)/documents/paymentCodes/$(d.codeId)).data;
      let after  = getAfter(/databases/$(db)/documents/paymentCodes/$(d.codeId)).data;
      return isStudent()
        && d.type == 'transfer' && d.status == 'pending'
        && d.fromUid == request.auth.uid && d.fromName == me().name
        && d.fromSeatNo == me().seatNo
        && d.amount is int && d.amount > 0 && d.amount <= me().balance
        && d.category in ['buy','repay','gift','other']
        && d.note is string && d.note.size() > 0 && d.note.size() <= 50
        && before.used == false && request.time < before.expiresAt
        && d.toUid == before.toUid && d.toName == before.toName
        && d.toSeatNo == before.toSeatNo
        && d.toUid != request.auth.uid
        && userDoc(d.toUid).active == true
        && d.participants == [d.fromUid, d.toUid]
        && d.createdBy == request.auth.uid && d.createdAt == request.time
        && !('balanceAfter' in d) && d.reversalOf == null && d.reversedBy == null
        && after.used == true && after.usedBy == request.auth.uid && after.txId == txId;
    }

    function validTeacherUpdate() {
      let changed = request.resource.data.diff(resource.data).affectedKeys();
      return !changed.hasAny(['type','amount','fromUid','toUid','participants',
                              'createdBy','createdAt','reversalOf','batchId','codeId'])
        // 狀態只能 pending → approved / rejected
        && (resource.data.status == 'pending' || !changed.hasAny(['status']))
        // reversedBy 只能由 null 設定一次
        && (resource.data.reversedBy == null || !changed.hasAny(['reversedBy']));
    }
  }
}

9.1 收款碼產生

const ALPHABET = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';        // 32 字，去除 I O 0 1
function newCodeId() {
  const bytes = crypto.getRandomValues(new Uint8Array(8));
  return Array.from(bytes, b => ALPHABET[b & 31]).join('');
}

9.2 掃描

  • 使用 qr-scanner：
    • iPad 指定後鏡頭 preferredCamera: 'environment'；電腦使用預設視訊鏡頭。
    • 先以 QrScanner.hasCamera() 偵測：沒有鏡頭（多數桌機）時，付款頁預設顯示「輸入 8 碼收款代碼」。
    • 代碼輸入框自動轉大寫、忽略空白，並即時檢查格式。
  • 必須在 HTTPS 下執行（GitHub Pages 預設為 HTTPS）；iPadOS「加入主畫面」模式亦支援相機。
  • 掃描結果只接受本站網址或 8 碼代碼格式，其他內容一律忽略，防止被導向外部網站。
  • 取得代碼後 getDoc(paymentCodes/{c})：
    • 不存在、已使用或已過期 → 顯示錯誤。
    • 有效 → 顯示收款人姓名與座號，進入填寫步驟。
